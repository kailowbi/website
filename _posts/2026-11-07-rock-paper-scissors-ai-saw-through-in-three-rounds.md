# 「コンピュータ将棋」ならぬ「コンピュータじゃんけん」をJevで作ってみた話

実際に遊べます → https://janken-training-app.playgroundsss.workers.dev

## きっかけ

将棋の世界には「コンピュータ将棋」というジャンルがある。人間のプロ棋士の指し手を研究し尽くして、打ち負かすことを目指す分野だ。じゃんけんでも同じことができないだろうか、とふと思った。

調べてみると、浙江大学の研究が面白かった。2014年にScientific Reportsに掲載された研究で、360人に300戦じゃんけんをプレイしてもらい、そのデータを分析している。結果、人間には無意識の「勝ち癖」があるらしい。

- 勝った直後は、**同じ手をもう一回出しやすい**(win-stay)
- 負けた直後は、**グー→チョキ→パー→グーの順に手をシフトしやすい**(lose-shift、時計回り)

じゃんけんが本当に1/3ずつのランダムなら、AIがどう頑張っても勝率は33.3%に収まるはず。でも人間の手にこういう偏りがあるなら、それを読んで先回りする「コンピュータじゃんけん」が作れるかもしれない。そう思って、週末に作ってみることにした。

## まずは単純に。ルールを書くだけのAI

技術的には全然難しいことをしていない。直前の相手の手と、勝ったか負けたかだけを見て、次の一手を予測し、その手に勝つ手を出す。それだけ。

- 相手が勝った → 次も同じ手を出すと予測 → その手に勝つ手を出す
- 相手が負けた → 時計回りにシフトすると予測 → シフト先の手に勝つ手を出す

条件分岐だけで書けるロジックで、機械学習も何もいらない。画面には一工夫入れた。AIの手を上に、自分の手を下に、180度回転させて表示したのだ。対戦相手と向き合ってる感じが出て、地味だけどこれだけで対戦してる感がぐっと増す。ちなみに180度回転は思いつきで、そこまで真剣に検討したわけじゃない。

## 「なんか勝てちゃうんだけど」

意気揚々と身内にテストしてもらった。返ってきたのはこんな数字だった。

18戦やって、**人間側10勝、AI側4勝、あいこ4回**。

投了です。理論通りなら、AIはある程度勝ち越せるはずなのに、全然勝ててない。

理由を聞いて分かった。

> 「なんとなく3回ぐらいやったらパターンが見えたかも」

これで全部説明がついた。自分が組んだロジックには、初手以外にランダム要素が一切なかったのだ。直前の手と勝ち負けさえ覚えていれば、AIが次に何を出すか完全に計算できてしまう。研究知見が間違っていたわけじゃない。「その知見を律儀にそのまま実装すると丸見えになる」という、実装側の落とし穴に自分で落ちていた。投了です。

## 応急処置:ちょっとだけブレさせる

とりあえず即効性のある対処から。予測にwin-stay/lose-shiftのルールを使う確率を85%にして、残り15%はランダムに手を出すようにした。完全な決定論を崩すだけの、その場しのぎの対応。でも実装は数行で済むし、体感的な「読まれてる感」もかなり減った。正直、この程度で効くとは思ってなかった。

## 本命:Jevに予測させて、本物の「コンピュータじゃんけん」に近づける

ルールベースはあくまで応急処置で、条件分岐の域を出ない。ここからが本題だ。実際にAIモデルに「次にどの手が来そうか」を予測させる方向を試すことにした。

使ったのは[TypeSafe AI](https://typesafe.ai/)というスタートアップの「Jev」というモデル。選択肢から確率付きで選ぶような構造化タスクに特化していて、普通のLLMよりかなり安く速く動くらしい。

これまでの対戦履歴を丸ごと渡して、「次に人間が出す手」を予測してもらう。ルールベースだと直前の1手しか見られなかったけど、これなら「何連勝したら同じ手を出しがちか」みたいな、もっと長い文脈のクセも拾える可能性がある。コンピュータ将棋が過去の棋譜を読み込んで指し手の傾向を掴むのと同じで、対戦履歴という「棋譜」を蓄積すればするほど相手の癖を精度良く読めるようになっていくはず、というのが狙いだった。

Jevの呼び出しはこんな感じ。`questions`に選択肢と基準(`criteria`)を渡すだけで、確率的な分類タスクとして答えを返してくれる。

```js
const upstream = await fetch("https://ai-gateway.lolipop.jp/v1/systemone", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${JEV_API_KEY}`,
  },
  body: JSON.stringify({
    model: "typesafe/jev-latest",
    state: buildHistoryState(), // "1回目: 人間はグーを出して勝った\n2回目: ..."
    questions: {
      next_human_hand: {
        type: "choice",
        instructions: "じゃんけんの対戦履歴から、次に人間がどの手を出すか予測してほしい。",
        criteria: { rock: "グー", scissors: "チョキ", paper: "パー" },
      },
    },
  }),
});

const { answers } = await upstream.json();
const predicted = answers.next_human_hand.choice; // "rock" | "scissors" | "paper"
```

`state`に文脈を積んで、`questions`に選びたい選択肢とその意味を書くだけでいい。普通のLLMだと「JSONで返して」って何回も念押ししても、たまに壊れた形式で返ってくる。でもJevは最初から選択式の答えを返す前提で作られてるっぽくて、そのへんの面倒がなかった。

呼び出し先はTypeSafe AI直ではなく、[ロリポップ！AIゲートウェイ](https://ai-gateway.lolipop.jp/)経由にしている。2026年9月18日〜24日の1週間、Jevが無料で使えるキャンペーン中だからだ。

APIキーが設定されてないときや通信に失敗したときは、元のルールベース予測に自動で戻る。そのときは画面にも「📐 ルールベース予測」と表示されるので、AIが効いてるかどうか一目で分かる。

## やってみて思ったこと

研究で示されてる人間の心理的な偏りは、多分本当にある。でも今回一番びっくりしたのは、その知見をどう実装に落とし込むかで結果がまるっきり変わるということだった。決定論的に律儀に実装すると、知識のある相手にはあっという間に見切られる。

ルールベース単体では3回で見切られる程度のものだったけど、Jevに乗り換えたことで「人間の癖を読んで先回りする」という最初の狙いには一歩近づけた気がしている。
